## Нативная Windows-проверка

Через навык computer-use запущен Release `Taktera.Mail.Desktop.exe`.
Проверены скриншот и accessibility tree настоящего Windows-окна:

- Три фиктивных письма и начальный выбор отображаются.
- Клик по первому письму дает фокус списку; Down выбирает второе и обновляет тему/тело чтения.
- Tab переводит фокус из списка на кнопку «Ответить».

Прямое уменьшение окна через рамку/системное меню не дало подтвержденного результата.
Для дальнейшей проверки создан временный локальный стенд в игнорируемом
`obj/NativeSmoke/NativeSmoke.csproj` с единственной ProjectReference на существующий Desktop.
Он не включен в solution, Git или приложение и не имеет собственных PackageReference.
Команда `dotnet build obj/NativeSmoke/NativeSmoke.csproj --configuration Release` прошла
с 0 ошибок/предупреждений. Стенд запускает настоящий App/MainWindow/ViewModel, задает
Width=850, Height=520 и показывает ClientSize/RenderScaling в заголовке окна.

В стенде F5 восстанавливает три письма, F6 задает длинную синтетическую фикстуру,
F7 очищает список, F8 сбрасывает выбор. Эти обработчики существуют только во временном стенде.
Для повторения на этой машине: запустить `obj/NativeSmoke/bin/Release/net10.0/NativeSmoke.exe`.
Стенд — локальный проверочный артефакт, не часть постоянной тестовой инфраструктуры;
для воспроизведения на другой машине его нужно подготовить отдельно.

На настоящем Windows-окне подтверждены ClientSize **850×520**, RenderScaling **1.00 (100%)**:

- Исходные три письма, поиск, тема и кнопки чтения видимы; боковая панель имеет прокрутку.
- Длинные тема/отправитель (300 символов без пробелов) переносятся в панели чтения;
  в списке обрезаются многоточием, не вытесняют время.
- Прокрутка мышью проходит от темы через 100 строк длинного текста до `END OF FIXTURE`.
  В конце видны обе кнопки, горизонтальное переполнение не наблюдается.
- F7 после длинного письма показывает пустую папку, приглашение выбрать письмо и счетчик 0;
  прежнее содержимое и кнопки чтения отсутствуют на экране и в accessibility tree.
- F5 восстанавливает список/первое письмо; F8 оставляет список из трех писем без выбора,
  показывая только приглашение в панели чтения. Клик по второму письму восстанавливает
  его тему/тело/кнопки.

Системный масштаб не изменялся. Попытка открыть SystemSettings.exe через computer-use
вернула отсутствие targetable window; повторное перечисление окон не обнаружило Settings.
Поэтому **150/200% остаются непроверенными**, а не считаются покрытыми масштабом 100%
или headless-тестами. Для их завершения нужна доступная Windows-сессия с переключением DPI
либо ручная проверка владельцем. Перемещение между мониторами также не проверялось.

Дополнительный нативный клавиатурный smoke на этом же масштабе:

- Tab: SearchBox → «Новое письмо» → выбранная строка списка → «Ответить» → «Переслать».
- Shift+Tab возвращает фокус с «Переслать» на «Ответить»; рамка фокуса видна.
- Home/End выбирают первое/последнее письмо, панель чтения обновляется.
- В длинном письме Tab из списка переводит фокус к «Ответить» и прокручивает панель
  до этой кнопки. Page Up прокручивает к предыдущим строкам, Page Down возвращает вниз.
- После очистки списка Tab проходит SearchBox → «Новое письмо» → SearchBox;
  скрытый список и кнопки чтения не получают фокус.

Это smoke существующего демо, не полная проверка accessibility/screen reader.
Поиск и почтовые команды остаются неработающими макетами и как функциональные сценарии
не принимаются. При повторном запуске стенда RenderScaling по-прежнему был 1.00.
