# 0001 — Layered architecture
Status: Proposed
Date: 2026-10-13

## Контекст
Восстановлены Desktop → Application → Domain; Application и Domain пусты.
Infrastructure из старой ветки не перенесен. Разрешено только восстановление демо;
данный ADR не утверждает создание адаптеров или расширение графа.
Демо создает ViewModel в App и не использует DI. Нужны тестируемость и малые накладные расходы.

## Альтернативы
- Все сервисы в Desktop: проще старт, но трудно тестировать и переносить.
- Четыре слоя с явными портами: понятные границы и умеренная сложность.
- CQRS/mediator, отдельные процессы и универсальные репозитории: лишние зависимости на данном этапе.

## Рекомендуемое решение
Domain содержит инварианты без IO/SDK/UI. Application содержит сценарии и узкие контракты.
Infrastructure реализует порты Application; сторонние MIME/SQL/OAuth типы не выходят наружу.
Desktop отвечает за MVVM и является composition root. После утверждения связывать сервисы
конструкторами в App; DI-контейнер добавлять только при необходимости управления lifetime.
Не использовать service locator. Приложение владеет временем жизни сервисов и отменой;
соединения — в ограниченной сессии аккаунта, операции — короткоживущие.
UI-коллекции обновляются на dispatcher, IO и обработка писем не блокируют UI.

## Риски
Singleton с изменяемым состоянием смешивает аккаунты; captive dependency удерживает соединения.
Избыточные интерфейсы увеличивают сложность без пользы. Параллельные операции могут нарушать lifetime.

## Последствия
Потребуются явные точки запуска/остановки и тестовые реализации портов.
Никаких изменений графа проектов, DI-пакетов или новых Infrastructure-реализаций на этапе 0.
Исторический ADR-001 остался в исходной ветке; он не утверждает этот ADR.

## Критерии проверки
Проверить отсутствие циклов и ссылок Domain на UI/SDK; unit tests работают без IO.
Сценарий закрытия окна отменяет операции и освобождает ресурсы в будущих lifecycle-тестах.
Сравнить старт/память до и после DI; контейнер без измеримой необходимости не добавлять.
