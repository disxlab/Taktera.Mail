## Архитектура

Фактический граф: Desktop → Application → Domain. Циклов нет.
Application и Domain содержат только csproj. Infrastructure отсутствует.
ViewModel создается в App, данные зашиты в MainWindowViewModel,
MailItem расположен в Desktop.Models. Для демонстрации это достаточно;
разделение бизнес-логики и инфраструктуры пока нельзя оценить на работающих сценариях.

Положительные стороны: минимум зависимостей, nullable включен во всех проектах,
MVVM через ObservableObject/ObservableProperty, типизированные compiled bindings,
минимальный code-behind, отсутствие синхронного сетевого кода и секретов в изученных исходниках.

### Исследование и исправление NU1903

Выполнены (через установленный dotnet.exe):

```powershell
dotnet list src/Taktera.Mail.Desktop/Taktera.Mail.Desktop.csproj package --include-transitive
dotnet nuget why src/Taktera.Mail.Desktop/Taktera.Mail.Desktop.csproj Tmds.DBus.Protocol
```

Подтвержден исходный путь:
`Avalonia.Desktop 11.3.6 → Avalonia.X11 11.3.6 → Avalonia.FreeDesktop 11.3.6 → Tmds.DBus.Protocol 0.21.2`.
Это зависимость X11/FreeDesktop, включенная кроссплатформенным Desktop-пакетом.
Уязвимость D-Bus сама по себе не доказывает эксплуатацию на Windows/macOS.

Выбран прямой PackageReference на **0.21.3** в Desktop — исправление,
[backport которого подтвержден разработчиком](https://github.com/advisories/GHSA-xrw6-gwf8-vvr9).
Это замена версии уже существующего runtime-пакета, без добавления нового сервиса.
Avalonia остается на 11.3.6; широкое обновление UI и переход на 0.92.0 не требуются
для устранения данного предупреждения. После обновления `nuget why` показывает 0.21.3
и в прямой ссылке, и в транзитивной цепочке. Override можно убрать, когда согласованная
версия Avalonia сама будет разрешать исправленный пакет.
